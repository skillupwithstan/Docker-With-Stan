## 🧩 Core Architecture Components

### 1. Docker Client (Your Command Center)

The Docker Client (`docker` CLI) is the primary way users interact with Docker. It accepts commands from the user and translates them into REST API requests, sending them to the Docker Daemon.

* **Examples:** `docker build`, `docker pull`, `docker run`

### 2. Docker Host (The Engine Room)

The Docker Host provides the complete environment to execute and run applications. It contains the following critical components:

* **Docker Daemon (`dockerd`):** The brain of Docker. It listens for API requests from the client and manages all Docker objects (Images, Containers, Networks, Volumes).
* **containerd:** A high-level container runtime that sits below `dockerd`. It manages the complete container lifecycle (downloading images, creating network interfaces, starting/stopping containers).
* **runc:** A low-level, lightweight CLI wrapper that actually creates and runs containers by interacting directly with the Linux kernel (Namespaces and Cgroups).

### 3. Docker Registry (The Library)

A registry is a scalable service used for storing and distributing Docker images.

* **Public Registry:** Docker Hub (default).
* **Private Registries:** AWS ECR, Azure ACR, or a self-hosted instance.

## 🛠️ Docker Objects

When you use Docker, you are constantly interacting with these four core objects:

| Object | Description | Analogy |
| --- | --- | --- |
| **Images** | Read-only templates containing the application code, libraries, and runtime instructions. | The architectural blueprint. |
| **Containers** | A live, runnable instance of a Docker image. It is isolated from the host machine and other containers. | The actual house built from the blueprint. |
| **Volumes** | The preferred mechanism for persisting data generated by and used by containers. Volumes survive container deletion. | The storage shed outside the house. |
| **Networks** | Allow containers to communicate with each other, the host machine, and external networks securely. | The roads connecting the houses. |

## 🔬 Under the Hood: Linux Kernel Features

Docker containers are not virtual machines; they do not have their own guest operating systems. Instead, `runc` leverages two powerful Linux kernel features to create the illusion of an isolated machine:

> [!TIP]
> 1. **Namespaces:** Provide **Isolation**. They ensure a container only sees its own processes, network interfaces, and file system. (e.g., *PID namespace, NET namespace*).
> 2. **Control Groups (cgroups):** Provide **Resource Limits**. They ensure a container only consumes a specific allocation of CPU, Memory, or Disk I/O, preventing one container from crashing the host machine.
